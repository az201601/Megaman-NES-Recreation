## Implemented in this checkpoint

Three GMS1.4.1760-compatible scripts:

- `scr_mm1_cutman_boss_decide`: all21 native strategy IDs5..25, including walk,
  initial jump choice/trajectory speed, short follow-up jump, delayed airborne
  throws, standing throw, stand/wait and hurt recoil decisions.
- `scr_mm1_cutman_boss_face`: native local-X distance/facing semantics, separately
  from locked movement direction.
- `scr_mm1_cutman_boss_animate`: packed dwell/frame counter, fire timer and blink
  countdown. Intended for one active world update, NOT Draw; renders must not
  advance gameplay or bypass pause.

User adaptations: rejected standalone26 cue remains absent; projectile creation
is an explicit throw request for integration. Final damage remains28HP and
normal/partial/full1/1/3; this checkpoint does NOT yet apply shot damage.

### Important original details preserved

- The random helper is `seed mod modulus`; it does not itself advance RNG. Seed
  production/global frame phase must be wired to the shared active-world clock.
- Walk speed288/256; initial jump upward speed1600/256; follow-up jump1248/256,
  horizontal192/256; recoil upward320/256, horizontal288/256.
- Initial horizontal jump speed uses signed-byte wrapping of absolute horizontal
  distance plus offset[-32,0,32], then integer division by50.
- Animation frame choice is from the PRE-advance counter. Fire high nibble selects
  a different animation table before fire countdown. Throw triggers at counter16,
  not at an invented second-based timer.
- Hurt initialization for Cut Man sets state14, not5. This was verified against
  original EF16 with native FightingBossNum=0. Recoil initialization only happens
  when changing to pose87; repeated blink>=31 updates don't reset velocity.
- State14 enters standing throw WITHOUT resetting the animation counter. Other
  branches reset it only where the original does.

## Kernel field contract (not object Create instructions)

Integer native-local coordinates `cm_x/cm_y` and target coordinates
`cm_target_x/cm_target_y`; `cm_target_ladder` substitutes native player pose9.
Scene positions currently remain world coordinates; an adapter must convert these
without losing native integer/subpixel comparison semantics.

`cm_state` strategy5..25; `cm_delay` byte; `cm_pose` native pose; `cm_anim` packed
counter; `cm_fire` byte; `cm_cutter`0/1/2; `cm_seed` byte; `cm_blink` byte;
`cm_sleep` lifecycle counter. Speeds `cm_speed_x/cm_speed_y` use1/256-pixel units,
positive Y speed means UP (not GameMaker's down-positive convention).
`cm_face_right` is visual facing; `cm_move_right` is locked horizontal travel.
`cm_wall` is horizontal collision output.

`cm_throw_requested` is reset at the start of each decision. An integration layer
must allocate/aim the cutter and only mark it out if creation succeeds; the kernel
does not prematurely increment `cm_cutter` or play a sound.

Required but **not yet implemented** `scr_mm1_cutman_boss_motion()` must update
facing first, sweep existing invisible geometry, update positions/speeds and
`cm_wall`, then return native-compatible landing status. It must be invoked exactly
where the kernel calls it, not as an unconditional extra physics pass each frame.

`cm_animation_frame` and `cm_draw_hurt` are animation outputs. The header passed to
animate must come from the table selected before cm_fire decrements. No sprite
resource/frame mapping has been introduced by this checkpoint.
