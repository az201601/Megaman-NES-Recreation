## Asserted observations

- Fresh B emits a basic shot. Holding for8 updates produces one shot, not auto-fire. Long holds/charge thresholds deliberately not established here.
- Projectile speed magnitude $0433 =1075/256 =**4.19921875 px/update**. Constant while shooter walks or changes direction; no inherited walk speed. Player turning does not reverse an existing bullet.
- Three basic-shot slots:1/2/3, active tag70hex, animation18hex. First fresh shots on updates1/3/5 allocate3/2/1. Further presses with all slots occupied produce no projectile, no shot command and no shooting-pose refresh. Hence the16-update pose timer is NOT a16-update firing cooldown.
- Rapid-tap case retries until a slot frees. First resumed emission is update29; old projectile cleanup occurs after the firing gate, so update27's fresh B still sees the occupied slot. Do not generalize the sample's29 as a universal cooldown.
- Original spawn writes use integer reference X+16 right, X-15 left, integer reference Y-1. They do not inherit player's fractional X/Y. Projectile moves once by4.19921875 in the SAME update it is created. Stationary X128 example ends first update at148.19921875 right or108.80078125 left. These are RAM references, NOT artwork top-left positions; extraction must establish sprite origin separately.
- Walking shot birth sees player's already-moved position. Example right walk at first shot reference130.59375 creates from integer130+16, then moves to150.19921875. GMS event ordering must be deliberate, not accidentally move a new projectile twice.
- Successful shot sets shooting flag34=1 and timer33=16. One tap keeps flag active on updates1..16, clears on17. Standing animation02, walk05, airborne08, ladder0B (hex IDs). Baseline counterparts01/04/07/0A. Actual shooting art still needs extraction.
- Standing, walking and airborne firing succeed. Jump motion proceeds while shooting in this sample.
- Continuing-ladder shot succeeds in either tested facing. Up/Down movement stops for16 updates starting on emission, remains attached and resumes1.296875/update when shooting flag clears. Neutral ladder holds normally. This is an intentional MM5 shooting interaction to integrate later, not a bug fix to the already-tested no-shoot ladder controller.
- Pressing Left+B on ladder emits left. Other simultaneous ladder release/top-entry/hurt/firing-priority combinations remain unmeasured.
- Fresh B DURING slide emits nothing. B simultaneous with Down+A slide start also emits nothing. Both cases remain sliding. Charge buffering/holding B through slide exit are not established by these short-tap tests.
- One original sound command1Ahex (=26) per successful emission. Blocked max-slot requests and slide taps add none. This identifies the request, not a published/approved sound recording. Future capture must use actual game audio with music stopped, following the previously approved landing-sound method; do not synthesize an approximation.
